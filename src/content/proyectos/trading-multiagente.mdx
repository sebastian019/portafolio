## Desafío

Quiero usar noticias financieras para apoyar decisiones de inversión, pero sin dejar que un modelo de lenguaje decida solo. Un LLM pequeño lee bien, pero juzga mal cuando se le pide demasiado de una vez.

A eso se suman tres exigencias:

- **Sin look-ahead:** el sistema no puede usar información que todavía no existía en la fecha que se está simulando.
- **Resultados reproducibles:** cualquier corrida tiene que poder repetirse y dar lo mismo.
- **Todo en mi propio equipo:** ningún dato se envía a servicios de IA en la nube.

## Arquitectura

El sistema tiene tres agentes con roles cerrados:

- **Cuantitativo:** lee precios y estima el régimen de mercado.
- **Percepción:** lee noticias y entrega, por empresa, un sentimiento y un nivel de confianza.
- **Manager:** acepta la señal o pide reanalizar.

Los agentes se comunican con mensajes estructurados y validados (JSON con Pydantic); ninguno escribe texto libre. La orquestación usa LangGraph con un patrón supervisor.

Después de los agentes, un optimizador convexo calcula los pesos del portafolio y todo queda registrado en una bitácora en Markdown. Un algoritmo evolutivo (CMA-ES) calibra los hiperparámetros. Todo corre en local con Llama 3.1 8B a través de Ollama, en una GPU de 8 GB.

## Solución y decisiones de diseño

- **El LLM solo entrega una señal acotada.** Produce un sentimiento y una confianza; el peso de cada activo lo decide un modelo matemático explícito que equilibra el retorno esperado con el riesgo (varianza y pérdidas extremas), con un tope por activo y solo posiciones largas. Así el juicio del modelo nunca se traduce directo en dinero, aunque sea simulado.
- **Todo lo demás es determinista y auditable.** Los indicadores, el control de riesgo, las ecuaciones y el optimizador no dependen del modelo de lenguaje, para que cada decisión se pueda revisar y explicar.
- **Veto de seguridad.** Si la confianza es baja o el modelo falla, el activo se excluye. Un error de conexión se registra como error y nunca se confunde con un veto silencioso, para no ocultar fallas.
- **Percepción trabaja en tres fases: buscar, leer y evaluar.** Cada documento leído se evalúa por separado y el resultado se combina con una regla fija, en vez de pedirle al modelo un juicio global, porque un modelo pequeño acierta más en tareas chicas y concretas.
- **Fuentes declaradas de antemano.** El modelo busca solo dentro de un conjunto definido (una fuente de medios y una oficial por país, para EE. UU. y Reino Unido) y no navega libremente, para controlar qué información entra al sistema. Las respuestas se guardan en caché para poder repetir cualquier corrida.
- **Salida estructurada, temperatura 0 y semilla fija.** Así las respuestas del modelo son lo más estables posible, y cada intento queda registrado para poder auditarlo.
- **Los límites los impone el código, no el prompt.** Qué fuentes se consultan, hasta qué fecha y cuántas consultas se hacen lo controla el programa, porque una instrucción en el prompt se puede ignorar y una regla en el código no.

## Cómo se evalúa

- **Backtest sin look-ahead** sobre un período posterior a la fecha de corte del modelo, para que no "recuerde" lo que pasó.
- **Conjunto de prueba separado,** con lo esperado escrito antes de correrlo y los parámetros congelados, para no ajustar el sistema a los resultados.
- **Paper trading con Alpaca:** operaciones simuladas, sin dinero real.
- Entre otras cosas, se comparará la evaluación global contra la evaluación por documento.

## Aprendizajes

- Un modelo pequeño lee bien pero evalúa mal: conviene dividir la tarea en pasos chicos y combinarlos con reglas fijas.
- Las reglas importantes deben estar en el código, no en el prompt.
- La reproducibilidad exige caché, semilla fija y registro de cada intento.
- El look-ahead es sutil: hasta una búsqueda web puede mostrar el presente en vez de la fecha simulada.
